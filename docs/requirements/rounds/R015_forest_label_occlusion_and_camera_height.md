# R015 - 森林页知识点标签避挡 + 相机高度滑块

状态：Accepted（已结束；森林页标签避挡与相机高度滑块成为当前基线）

创建日期：2026-06-30

## 背景

R014 完成后，森林页顶部栏与知识簇导览窗已改为浅色 UI，导览窗也具备拖动/隐藏能力。但用户运行查看后认为知识点名称标签的视觉方案仍未达标：当前“白底黑字”标签虽然比原先“黑体白边”清晰，但会遮住树冠，甚至与知识簇标题发生重叠遮挡。同时，用户希望有一个更直接的相机高度/视角高度调节控件，便于不用右键拖拽也能快速找到舒服的观察角度。

本轮承接 R014，专注两个微调点：**知识点名称标签的遮挡/层级问题**，以及**右上角相机高度滑块**。

## 用户真实反馈

逐字记录：

1. “白底黑字的设计感觉也不是很好，关键是还把树给挡住了大半，有的还会和知识簇标题重合遮挡”
2. “可以增加一个调整相机高度位置的滑块条在右上方，方便用户寻找最佳视角”

## 当前实现现状

- R014 后，知识点名称标签使用 `.forest-tree-label`，表现为暖白小底牌 + 深色文字 + 轻阴影；在悬停、拉近或簇跳转近景下显示。
- 该方案的主要问题不是“看不清”，而是**遮挡太强**：标签底牌会挡住树冠，也会和知识簇标题互相压住。
- 现有相机俯仰主要通过右键拖动（或 Ctrl/Meta + 左键）调整，内部状态为 `scene3d.js` 的 `this._state.phi`，范围约 `[0.62, 1.44]`，默认最佳视角 `phi=1.0`。
- 当前顶部栏右侧已有“跳到知识簇”下拉与重置按钮；本轮新增的滑块应放在右上方，不能遮挡主要操作，也不能破坏现有相机交互。

## 本轮目标

- 让知识点名称标签从“白底黑字遮挡物”变成更轻、更懂避让的提示层：能读，但不盖住树，也不和知识簇标题抢层级。
- 在右上方增加相机高度/视角高度滑块，让用户可以直观调整观察高度，快速找最佳视角。

## 具体需求

### 需求 1：重做知识点名称标签的遮挡策略

执行智能体需要重新设计知识点名称标签方案，重点解决**遮挡树冠**与**遮挡知识簇标题**，而不是继续单纯调字号/颜色。

必须满足：

- 知识点标签不能用大块白底黑字面板覆盖树冠；标签应更轻、更透明、更像提示层。
- 标签不得与知识簇标题重叠遮挡；知识簇标题优先级高于知识点标签。
- 默认全景不应出现批量标签遮挡画面。
- 簇跳转近景、拉近、悬停单棵树时，标签仍能帮助用户识别知识点，但不能牺牲树形可见性。
- 长标题需要截断、换行或改用悬停 tooltip 展示完整标题，不能用过宽底牌横扫一片树。

可选实现方向，执行智能体需结合截图选择最合适的一套：

- **优先推荐：悬停/选中为主，批量标签为辅**。默认和普通近景不批量显示所有知识点标签，只在悬停、键盘聚焦或点击选中某棵树时显示该点名称；如仍保留近景批量标签，要加密度上限与避让。
- **改用轻量浮动提示**：比如透明度较高的小 tooltip、细边框、轻阴影、非纯白底；标签可以偏移到树冠旁边，用小箭头/细线指向树，而不是压在树冠正上方。
- **做基础碰撞避让**：至少检测树标签与知识簇标题 DOM 的屏幕矩形重叠；发生重叠时隐藏或偏移树标签，簇标题优先保留。
- **做树标签之间的密度控制**：近景批量显示时，避免标签互相叠成一团；可以按重要度、屏幕网格或最大可见数量筛选。
- **保留完整信息路径**：如果标签平时更克制，用户仍应能通过悬停/点击或右侧详情看到完整知识点名称。

不得做：

- 不要把知识簇标题也一起改成不明显；用户前一轮已经明确知识簇文字基本可接受。
- 不要为了避挡而完全取消所有知识点名称提示；至少悬停/选中时要有清晰名称。
- 不要引入重型标签布局库。

### 需求 2：右上方增加相机高度 / 视角高度滑块

在森林页右上方增加一个轻量滑块控件，用于调整相机高度/视角高度，让用户不用右键拖动也能找舒服视角。

具体要求：

- 控件位置：右上方，建议在顶部栏下方或顶部栏右侧形成小型浮层，避免遮挡搜索、知识簇下拉和重置按钮。
- 控件风格：沿用 R014 后的浅色 chrome，白色/暖白面板、深色文字、绿色强调，不能像浏览器默认裸控件。
- 控件文案建议为“视角高度”或“相机高度”，可配一个简短数值/刻度；不需要大段说明。
- 滑块应控制当前相机俯仰/高度感，建议映射到 `scene3d.js` 的 `phi` 或等价相机高度状态：
  - 一端更俯视、更高；
  - 一端更贴近地平线/更低，必要时保留 R013 的仰望天空能力；
  - 范围应沿用或合理收敛现有安全范围，不能让相机钻到地下、翻转或失去森林。
- 滑块与现有相机交互要同步：
  - 拖动滑块后画面立即更新；
  - 右键拖动调整俯仰后，滑块值也应尽量同步到当前视角；
  - 点击重置按钮后，滑块回到默认最佳视角值；
  - 点击知识簇跳转或搜索跳转后，不应把用户刚调好的高度意外重置，除非明确使用重置按钮。
- 控件不能破坏现有右键转视角、左键平移、滚轮缩放、跳转知识簇、搜索跳转、导览窗拖动/隐藏。
- 滑块需有基础可达性：`aria-label` 或可见标签，键盘可调。

### 需求 3：截图自检与微调

本轮是视觉/交互微调，执行智能体必须截图自检并迭代：

- 默认全景：确认没有批量知识点标签遮挡树冠或知识簇标题。
- 悬停单棵树：确认该知识点名称清楚，但不挡住大半树冠。
- 簇跳转近景：确认标签策略在树密集区域不糊、不压知识簇标题。
- 拖动相机高度滑块到高/中/低三档：确认视角变化自然，滑块值与画面一致。
- 调整滑块后再使用右键拖动、重置、簇跳转：确认不会互相打架。

## 非目标

- 不改知识点/知识簇数据，不改数据管线。
- 不重做森林布局、树形、天空、地面、云、阴影或簇区域曲线。
- 不大改顶部栏、知识簇导览窗拖动/隐藏能力；R014 已完成的能力应保留。
- 不改首页、阅读页、右侧知识点详情面板。
- 不重新定义整体相机模型；只暴露一个用户可控的高度/俯仰调节入口，并保持现有鼠标交互。

### 已完成需求

- **需求 1（知识点名称标签避挡）**：默认全景和普通近景不再批量铺开树标签；极近视角只允许少量重要可见标签参与显示，并继续经过碰撞检测降级隐藏。悬停标签保持可读，并优先尝试右上、左上、右下、左下多个偏移位置。
- **需求 1（层级与碰撞）**：树标签摆放时会读取知识簇标题 DOM 的屏幕矩形，把簇标题作为更高优先级占位；若普通树标签与簇标题或其他树标签冲突，则隐藏该树标签。悬停标签在无完全干净位置时仍保留显示，避免用户失去识别路径。
- **需求 1（视觉样式）**：`.forest-tree-label` 从暖白大底牌改为小尺寸深色半透明 tooltip，带最大宽度、省略号和细连接线，不再以白底黑字块压住树冠。
- **补充修正（近景自动显示）**：拉近/簇近景下小知识点名称会自动显示，不再必须鼠标悬停；自动标签候选只从当前屏幕附近的可见树中选取，避免屏幕外树占用标签名额。
- **二次补充修正（簇级全量标签）**：点击知识簇跳转，或滚轮拉近到簇级阅读距离后，屏幕内可见知识点名称全部显示，不再按数量上限筛选；若避让算法找不到完全干净的位置，也会兜底显示小标签，优先满足近景阅读完整性。
- **需求 2（右上视角高度滑块）**：`ForestMapPage.tsx` 新增右上浮层滑块，显示“视角高度”和“高 / 中 / 低”当前档位，带 `aria-label`，键盘可调；样式沿用 R014 浅色 chrome。
- **需求 2（相机同步）**：`scene3d.js` 暴露 `getCameraHeight`、`setCameraHeight`、`onCameraChange`，把滑块 0-100 映射到现有安全 `phi` 范围；滑块拖动、右键俯仰拖动、重置、知识点跳转和知识簇跳转后都会同步当前滑块值。
