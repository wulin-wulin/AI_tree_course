# R016 - 阅读页内容展示优化 + 领域学习路径

状态：Implemented

创建日期：2026-07-09

## 背景

当前项目已有 603 个《人工智能原理》知识点、3D 森林导览和知识点阅读页。但阅读页的内容展示仍偏“把字段直接放上去”：公式只是字符串显示，正文中的换行、列表、代码块、加粗、内联公式等内容形态没有被很好识别；部分知识点里的公式写法也比较混杂，导致展示效果不稳定。

此外，用户希望从“按章节浏览”升级到“按学习目标组织路径”：当学习者想学习某个领域时，系统能从所有知识点里筛出相关知识点，排成一个有序学习列表，并在森林导览页用一条虚线路径把这些知识点串起来，让学习者可以按路径顺序学习。

本轮同时处理两个方向：**阅读页内容呈现质量**和**领域学习路径功能**。

## 用户真实反馈

逐字记录：

1. “内容展示界面需要调整，有的公式渲染没做好，还有的是要跟据内容看看我们的展示格式要怎么调整适应一下，要看一下然后实现，总之就是章节的知识点内容那个页面需要优化一下”
2. “增加一个功能是，用户想学习某个领域知识内容的时候，我们可以将我们的所有知识点中和用户想学的领域有关的知识点筛选出来，然后将他们排成一个有序列表，读者可以按照顺序去学习，然后再章节导览界面使用一个虚线路径来将知识点串联起来 你应该能理解我说的是什么意思”

## 当前实现现状

- 阅读页入口：`src/components/ReadingPage.tsx`。
- 阅读内容组件：`src/components/KnowledgeDetailPanel.tsx`。当前主要直接渲染 `point.coreIdea`、`point.principles`、`point.formula`、`applications`、`comparisons` 等字段。
- 公式展示：`src/components/FormulaBlock.tsx` 和 `KnowledgeDetailPanel` 中的 `.formula-block` 目前只是把公式字符串放进普通 `div`，未做真正数学排版。
- 数据里存在多种文本形态：`$...$`、`$$...$$`、换行段落、Markdown 风格 `**加粗**`、项目符号、编号、代码围栏、伪代码、长公式、局部不规范公式字符串等。
- 森林导览页：`src/components/ForestMapPage.tsx` + `src/forest/vendor/scene3d.js`。当前支持搜索知识点、跳到知识簇、点击树进入阅读页、相机高度滑块（R015 已 Accepted）。
- 导航数据：`src/data/courseNav.ts` 从 `src/data/index.json` 读取 603 个点并按「簇顺序 + 簇内顺序」形成默认课程序列；完整详情在 `src/data/points/*.json`，由 `loadPoint` 按需加载。

## 本轮目标

1. 优化知识点阅读页，让公式、正文段落、列表、代码/伪代码、长内容等都能根据内容形态更自然地展示。
2. 新增“领域学习路径”能力：用户输入想学的领域，系统筛选相关知识点、生成有序学习列表，并在森林导览页用虚线路径串联这些知识点。

## 具体需求

### 需求 1：阅读页内容展示与公式渲染优化

执行智能体需要先抽查一批代表性知识点，再实现展示优化。不要只调 CSS；要根据真实内容形态设计渲染方案。

必须覆盖：

- **公式渲染**
  - 支持正文和公式字段中的常见数学写法：`$...$`、`$$...$$`、`\(...\)`、`\[...\]` 等。
  - 行内公式应与中文段落自然排版；块级公式应居中或独立成块，长公式可横向滚动，不撑破页面。
  - 对不规范或无法解析的公式要优雅降级：显示可读原文，不让页面崩溃，不出现大片异常样式。
  - 可引入轻量成熟的数学渲染方案（例如 KaTeX 或等价方案），但不能依赖外部网络 CDN。
- **正文结构化展示**
  - `coreIdea`、`principles`、`applications`、`comparisons` 等字段中的换行、段落、列表、编号、`**加粗**`、内联代码、代码围栏/伪代码需要更像“学习材料”，而不是一整段纯文本。
  - 对包含“关键公式 / 伪代码思路 / 直观例子 / 关键变体”等明显小节的文本，可做轻量分段或小标题处理；不要为了追求完美解析而重写全部数据。
  - 代码/伪代码需要用等宽字体、块状背景、保留换行与缩进。
  - 长段落需要改善行宽、行距和层次，避免阅读疲劳。
- **内容适配**
  - 根据不同知识点内容的实际情况适配：只有短概念的点不要被过度包装；公式/代码/列表很多的点要有更清晰的层级。
  - 保持当前阅读页主结构：标题、摘要、核心思想、图示/动画、基本原理、折叠资料区、右侧章节 dock。可以优化布局和渲染细节，但不要重做整套阅读页导航。
- **抽查与修正**
  - 执行智能体至少抽查这些类型的样例：长公式点、内联公式点、代码围栏/伪代码点、普通短文本点、列表很多的点。
  - 如果发现少量明显坏掉的数据公式字符串，可以局部修正对应 `src/data/points/*.json`；不要大规模改写 603 个知识点内容。

建议关注的样例（可替换，但执行反馈需说明实际抽查了哪些）：

- `3d-convolution`：长公式、代码/步骤混合。
- `value-iteration`：贝尔曼公式。
- `vae`：公式与特殊符号混合。
- `zero-shot-prompting`：代码围栏/伪代码。
- `tree-of-thoughts`：步骤、伪代码与公式混合。

### 需求 2：领域学习路径生成

在 `/ai` 森林导览页新增“领域学习路径”功能。用户输入一个想学习的领域或主题，系统从全部知识点里筛选相关知识点，排成一个有序列表。

功能要求：

- **输入入口**
  - 在森林导览页提供清晰入口，例如顶部栏或右侧/左侧轻量面板，名称可为“学习路径”“按领域学习”等。
  - 用户可输入领域关键词，如“大语言模型”“计算机视觉”“强化学习”“语音识别”“图神经网络”等。
  - 提供生成路径、清空路径的操作；可保留最近一次路径（localStorage 可选）。
- **筛选相关知识点**
  - 需要在所有 603 个知识点中筛选，而不是只筛当前章节。
  - 匹配信息至少包括：知识点标题、别名（如有）、所属知识簇、摘要/核心思想/关键词等可用字段。
  - 可以先用本地规则实现，不要求接后端或 LLM；如需要加载完整点详情，应注意性能并做缓存/异步状态。
  - 结果为空或太少时，应给出可理解的空状态/建议，而不是静默失败。
- **有序学习列表**
  - 结果不是简单搜索结果堆叠，而是有学习顺序。
  - 排序应兼顾相关性与学习先后：优先把基础/前置概念放前面，再到方法、模型、应用；可以结合现有课程顺序、簇顺序、前置知识字段、标题/关键词相关性来排序。
  - 列表中展示序号、知识点名称、所属知识簇，并可点击定位森林中的点或进入阅读页。
  - 提供“开始学习”入口，进入路径中的第一个知识点。
  - 学习者应能按路径顺序继续学习。最低要求：路径面板提供明确的下一步列表；更好方案是在阅读页显示当前路径进度并提供路径上一点/下一点导航。
- **路径状态**
  - 生成的路径应在当前会话内保持，用户从森林页进入阅读页再返回时不应立刻丢失。
  - 不要求账号级保存或后端保存。

### 需求 3：森林导览页虚线路径串联

当领域学习路径生成后，森林导览页需要用一条虚线路径把路径中的知识点按顺序串联起来。

具体要求：

- 虚线路径连接的是筛选出的有序知识点，而不是连接所有同领域簇。
- 路径应画在 3D 森林场景里，跟随相机移动/缩放自然显示；可以在地面上略微抬高，避免与地面/簇边界混在一起。
- 路径样式应明显但不刺眼：虚线、柔和高亮色、必要时带起点/终点或序号标记。
- 路径中的知识点应有轻量高亮或编号提示，帮助用户对应列表顺序。
- 清空路径后，虚线和高亮全部消失。
- 路径不应破坏已有能力：点击树进入阅读页、搜索、跳到知识簇、相机高度滑块、知识簇导览窗拖动/隐藏、标签显示都应继续可用。
- 如果路径点跨度很大，执行智能体需要处理可读性：可以提供“查看完整路径 / 聚焦路径 / 跳到当前路径点”等辅助操作，具体方案由执行者根据截图决定。

### 需求 4：阅读页中的路径学习体验

为了让“按顺序学习”真正成立，阅读页需要能感知当前学习路径。

最低要求：

- 从路径列表点击“开始学习”进入第一个点后，阅读页能显示当前路径进度，例如“学习路径 · 第 1/12 点”。
- 阅读页提供路径上一点/下一点导航，不与原有“全课程上一点/下一点”混淆。
- 提供返回森林路径或查看路径列表的入口。
- 如果用户直接从普通章节进入阅读页，不应显示路径模式或影响原有章节导航。

实现可选：

- 使用 localStorage/sessionStorage 保存当前学习路径 ID 列表与查询词。
- URL 可加 query/hash 状态，但不要破坏现有 `/ai/:chapterId/:pointId` 路由刷新可用性。

## 非目标

- 不接后端、数据库、账号系统或外部 LLM。
- 不要求语义嵌入或真正自然语言理解；本轮可用本地规则/关键词完成第一版。
- 不重写 603 个知识点数据，不大规模改内容。
- 不重做森林布局算法，不改树形、天空、地面、云、簇区域曲线。
- 不把当前章节 dock 删除；路径学习应作为新增模式，与原章节导航共存。
- 不改首页课程卡体系。
- 不解决移动端完整手势体验；桌面视口先达标。

- `npm run build` 通过。
- 阅读页公式不再只是原始字符串：行内公式、块级公式、长公式均有明显改善；无法解析的公式优雅降级且页面不崩。
- 阅读页能更好展示段落、列表、加粗、代码/伪代码、长内容；至少抽查 5 个代表性知识点并在执行反馈列出。
- 原有阅读页功能不回退：章节 dock、上一点/下一点、图示/动画、折叠资料区、返回森林仍可用。

- 生成结果是有序学习列表，不是无序搜索结果；列表项可定位/进入阅读页。
- 森林页能用虚线路径按顺序连接筛选出的知识点；清空路径后虚线和高亮消失。
- 从路径开始学习进入阅读页后，阅读页能显示路径进度并提供路径上一点/下一点导航；普通阅读模式不受影响。
- 无控制台错误；桌面视口下 UI 不明显遮挡、错位或卡顿。
- 涉及 UI/视觉的改动必须按协议截图自检：阅读页公式/代码样例、森林页路径面板、虚线路径全景、路径点近景、阅读页路径模式。
