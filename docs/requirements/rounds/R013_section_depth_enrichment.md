# R013 - 知识点阅读页内容加厚（小节深度扩充）

状态：Draft

创建日期：2026-06-07

## 背景

R004–R012 把 Level 1 章节导览打磨成了有内容感的徒步长卷，导航与场景感已经成熟。但人类用户在使用中发现：**点进任意一个小节（Level 2 知识点阅读页）后，内容仍然太单薄**——目前每页只有「核心思想（1 句）+ 基本原理（2–3 条）+ 折叠的术语/对比/应用 + 延伸思考（1 句）」，读完很快、信息密度低，离「能学到东西」还有距离。

本轮聚焦 **Level 2 知识点阅读页的内容深度**，在不改变三级导航结构的前提下，给每个小节补充更有学习价值的内容块，让单页「读得下去、学得到」。

本文件当前为 `Draft`，仅用于沉淀讨论。执行智能体读到 `Draft` 时应停止实现，待需求讨论窗口确认后置为 `Ready`。

## 用户真实反馈与想法

> 原话保留：

- 「我现在感觉每一小节点进去之后的内容太少了太单薄了。」
- 「（应该）把每个小节页做厚——增加直觉解释、可展开的正文、例子、自测题等，重点是深度。」
- 「注意 UI 排布需要和整体系统契合。」

## 已确认的关键决策

经需求讨论窗口（可视化方案对比）逐项确认：

- **方向**：选 **A「把每个小节页做厚」（纵向加深）**，不增加知识点数量（维持现有 49 个点），靠单页深度破除单薄感。横向补充更多小节属未来轮次，不在本轮。
- **落地策略**：选**「试点优先」**——先扩展数据模型与渲染、并**完整写满一个章节作样板**，由需求讨论窗口审样板的文字质量与排版手感，确认后再批量补完其余章节（其余章节的内容铺开属本轮之后的迭代或新轮次）。
- **试点章节**：`搜索与问题求解`（`search-solving`，共 7 个知识点）。选它因为同时含公式/例题型硬核点（启发式函数、A* 搜索、Alpha-Beta）与流程型点（BFS/DFS/Minimax），能把全部新内容块压测一遍，定下来的写作 + 排版风格可复用到其余 7 章。
- **要加哪些内容块**（5 类，用户多选确认；**不含**「常见误区」，本轮先不做）：
  1. **通俗直觉 / 类比**（A）
  2. **展开讲讲 / 详细正文**（B，默认折叠）
  3. **例题 / 分步推导**（C）
  4. **自测题**（E，答案点击展开）
  5. **知识点关联**（F，可点跳转）
- **视觉契合（用户强调）**：新内容块必须服从现有阅读页的**「单章一色 + color-mix 派生」**视觉语言，不引入彩虹多色、不自造控件。

## 本轮目标

在知识点阅读页（`KnowledgeDetailPanel`）中，以**与现有系统视觉一致**的方式，新增 5 类可选内容块；并把**试点章节「搜索与问题求解」的 7 个知识点全部写满**这 5 类内容，作为后续批量铺开的样板。读完试点章应明显感到「内容厚了、读得下去、能自测」，而非走马观花。

## 具体需求

### 1. 数据模型扩展（`src/data/courseKnowledge.ts`）

在 `KnowledgePoint` 类型上新增 5 个**可选**字段（全部 `?`，未填的知识点照常渲染、不显示对应块，保证对现有 42 个点零破坏、可增量铺开）：

```ts
intuition?: string;                    // A 通俗直觉/类比（一段）
deepDive?: string[];                   // B 展开讲讲（多段，默认折叠）
workedExample?: {                      // C 例题/分步推导
  setup: string;                       // 题面/前提
  steps: string[];                     // 分步
  takeaway?: string;                   // 一句话结论（可选）
};
quiz?: { q: string; a: string }[];     // E 自测题（答案点击展开）
relatedPoints?: string[];              // F 知识点关联：存知识点 id（不复用 prerequisites 文字标签）
```

- `relatedPoints` 存的是 `KnowledgePoint.id`，渲染时用 `findPoint` 解析为标题并生成可点跳转（点不存在的 id 应安全跳过，不报错）。

### 2. 渲染（阅读页内容块）

- 每个新块各自拆为小组件（建议 `IntuitionBlock` / `DeepDiveBlock` / `WorkedExampleBlock` / `QuizBlock` / `RelatedPointsBlock`），避免把 `KnowledgeDetailPanel` 撑大；其中仅自测题（答案展开）和「展开讲讲」折叠涉及局部状态/原生 `<details>`。
- 每块仅在对应字段存在且非空时渲染。
- 整页从上到下的**插入顺序**（灰=现有，新块插入位置如下）：
  1. 顶部导航（现有）
  2. 标题 + 标签 + 摘要（现有）
  3. 核心思想（现有）
  4. **通俗直觉（A）— 常驻**
  5. 图示 + 动画（现有）
  6. 基本原理 + 内联公式（现有）
  7. **例题 / 分步推导（C）— 常驻**
  8. **展开讲讲（B）— 默认折叠**
  9. 参考折叠组：术语/对比/应用/前置（现有）
  10. **知识点关联（F）— 常驻细条**
  11. **自测题（E）— 常驻，答案点击展开**
  12. 延伸思考（现有，结尾）

### 3. 视觉契合规则（强约束）

1. **只用本章 accent**：所有新块的颜色一律由现有 `--detail-accent` / `--detail-soft` 经 `color-mix` 派生，不引入任何新色；同一页单色调，换章自动变色，与现有页面一致。
2. **沿用现有 kicker 小标题语汇**：新块标题用现有 `.reading-lead-kicker` 那类小号（`font-weight:850` + accent 染色 + `letter-spacing:.04em`）小标题，而非大号 `<h3>`，保持「安静分区」节奏。建议文案：`通俗直觉`、`动手算一算`、`想深入`、`随手测一测`、`顺着往下学`。
3. **折叠块复用现有 `.reading-aside`**：展开讲讲（B）与自测答案（E）的折叠，复用现有 `<details>`/`.reading-aside` 的底色、圆角、箭头，不自造折叠控件。
4. **引述型块复用引述质感**：直觉（A）、例题（C）用一条 accent 左边线 + `--detail-soft` 极淡填充的轻底卡，与现有 `.reading-lead` / `.reading-coda` 同质感。
5. **关联（F）复用术语云胶囊**：用现有 `.term-cloud` 胶囊样式做成可点 chip，本节高亮、前后点可跳转。
6. **对齐现有尺寸 token**：圆角 `11–12px`、正文约 `0.96rem`、段距 `24–30px`，不新引入尺寸体系。

### 4. 试点章节内容（必须全部写满）

为 `search-solving` 章的 7 个知识点各补齐上述 5 类字段，内容必须**准确、符合《人工智能原理》课程口径**：

- `state-space-search` 状态空间搜索
- `breadth-first-search` 广度优先搜索
- `depth-first-search` 深度优先搜索
- `heuristic-function` 启发式函数
- `a-star-search` A* 搜索
- `game-search-minimax` 博弈搜索与 Minimax
- `alpha-beta-pruning` Alpha-Beta 剪枝

`relatedPoints` 优先在本章内构成「前置→本节→延伸」链条（如 启发式函数 → A* 搜索 → 博弈搜索），可少量跨章关联。

## 非目标

- 不改变三级导航结构与路由；不动首页书架（Level 0）与章节长卷（Level 1）。
- 不新增知识点数量（横向扩充留待后续轮次）。
- 本轮**不做「常见误区」块**（用户本轮未选）。
- 不批量改写试点章之外 7 章的内容（先审样板；其余章节铺开属本轮之后的迭代/新轮次）。
- 不引入后端、外部图片资源或新的重型依赖。
- 不改动既有字段的语义与现有内容；新字段一律可选、向后兼容。

## 验收标准

> 验收方式沿用既往：以需求讨论窗口（人类用户）**主观评审**为准，`npm run visual:review` / 截图作为佐证。

- `KnowledgePoint` 新增 5 个可选字段；未填字段的知识点（其余 42 个点）渲染不受影响、无报错。
- 阅读页按既定顺序渲染 5 类新块，折叠/答案展开交互正常，关联 chip 可点跳转到对应知识点。
- 5 类新块在视觉上与现有阅读页一致：单章一色、kicker 语汇、复用折叠/胶囊/引述样式；切到不同章节颜色随 accent 自动变化，无彩虹多色。
- 试点章「搜索与问题求解」7 个知识点的 5 类内容全部写满，内容准确、可读、对学习有实际帮助；通读该章 7 页明显不再单薄。
- 桌面与移动端排版正常，长页不拥挤、层次清晰。
- `npm run build` 通过；执行智能体已按协议自检截图。
