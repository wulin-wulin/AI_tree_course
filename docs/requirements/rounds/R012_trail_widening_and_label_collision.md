## 背景

R010+R011 后，森林长卷基线已经成型并被采纳。继续打磨时人类用户提出两点**小微调**：

1. **路径整体可以再拉宽一点**：节点 / 树 / 标题等元素尺寸保持不变，仅版面"松一点"。
2. **文字偶有重叠**：默认左右交替放在树苗旁的小节标题，相邻节点垂直距离较近时会与对侧标题相互压住——需要在检测到重叠时把其中一个标题**摆到树苗的另一边**。

> 用户额外说明：「路径太过单调」是已知问题，但**本轮先不管**，留待下一轮专门做微调。

## 已确认的关键决策

- **只动 Level 1（`/ai` 章节长卷地图）**；不改首页书架（Level 0）、阅读页（Level 2）、路由、数据。
- **保留 R010+R011 已有基线**：长卷主体、49 小节 + 8 章地标 + 不同树种、向心 Catmull-Rom 曲线、分段染色、单预览卡、按小节进度、纤细顶栏、全展开拆白框、右侧章节序列索引（含可收起为指南针 + 收起态居中）、Portal 修复 + 严格作用域——全部保留无回退。
- **不动**节点 / 树 / 标题等元素**尺寸**；本轮仅放宽版面与解决标题重叠。
- **暂不处理路径走向的"单调"问题**（留待下一轮）。

## 本轮目标

把长卷版面整体「松一点」：节点之间在横向和纵向上都更宽裕，呼吸感更好；同时解决相邻小节标题的相互遮挡问题——检测到与对侧/邻侧标题冲突时，把当前标题摆到树苗的另一边。

## 具体需求

### 一、路径整体拉宽（不改元素尺寸）

- 在 `ChapterMapPage` 的 `computeLayout` / 场景宽度计算里，把桌面端（≥1024px）的内容带子最大宽度从当前 `min(w - sidebarReserved, 1040)` **放宽到 `min(w - sidebarReserved, 1200)`**（或同量级值，由执行视实际效果取最佳；以「明显更松、但不夸张拉满」为度）。
- 同步**适度增大每行波浪的拱幅 `bowAmp`**（当前桌面 52 / 移动 34），让横向波浪更舒展、节点彼此横向间距更明显。建议参考增幅 `bowAmp ≈ +20%`（如 52 → 64、34 → 40），具体由执行视觉评审定。
- 纵向 `rowH` 可作小幅放松（如 300 → 320–340），让上下两行节点 / 标题更不挤；不要大改导致整页过长。
- **节点 / 树 / 小节标题字号 / 地标尺寸不变**——本轮不重做节点视觉。
- 中屏 / 移动端（<1024）原则不动 `perRow` 与节点尺寸；如执行评估窄屏也能等比放松 1–2 点（rowH / bowAmp）使呼吸感更一致，可以做，但保证「移动端不再溢出 / 不出现新挤压」。

### 二、文字重叠时自动换边

> 现行规则：小节标题默认按 DOM 顺序在树苗左 / 右交替；执行反馈里提过桌面"在树苗旁、沿路左右交替排布，避免互相遮挡"。但相邻节点在波浪转折或行末弧转处垂直接近时仍可能重叠。

- 在节点布局完成后，对所有**小节标题**（不含地标章节名）做一次**重叠检测 + 换边修正**：
  - 估算每个标题的包围盒（标题文字宽度可用近似字符宽度估算或测量 DOM；纵向用行高近似）。
  - **按节点 DOM 顺序依次放置**；每放一个标题前，先用其默认侧（沿用现行交替规则）算包围盒，与**已放置的标题包围盒**比对；
  - 若与任一已放置标题相交 → **翻到对侧**（树苗另一边）；若对侧也相交 → 选**冲突更小的一侧**（重叠面积小者）；
  - 翻边只影响**标题位置（左 / 右锚点）**，不改树苗 / 小径 / 节点 / 章节顺序，也不动地标章节名（地标按 R010 已有规则放置）。
- 翻边后标题与树苗的距离 / 锚点对齐保持与默认侧一致（仅水平方向镜像）；颜色 / 字号 / 折行规则不变。
- **稳定性**：换边的判定必须**确定性**（同一组节点在多次重算 / 切换收起态后产生相同的换边结果），避免重排时标题左右乱跳；建议在每次 `computeLayout` 末尾跑一次完整重排（而不是增量），并按固定顺序（DOM 顺序）做决定。
- **可达性**：换边不影响 `Tab` 顺序、`aria-label`、聚焦预览卡逻辑（标题位置只是视觉锚点；DOM 仍按旅程顺序）。

### 三、与 R010+R011 既有功能的关系

- R011 的章节序列索引侧栏 / 指南针 / 收起态居中：拉宽后，**展开态** `sidebarReserved=200` 仍生效；**收起态** `sidebarReserved=0` 让长卷在主视区居中，新拉宽值（如 1200）随之生效。两种状态下都应呼吸感更好。
- R010 的章节分段染色 / 装饰背景树 / 向心 Catmull-Rom 曲线、R009 单预览卡 / 顶栏进度 / 可达性 / `prefers-reduced-motion` 等——全部保留无回退。

## 迭代 1 反馈

> 由需求讨论窗口在审核 Implemented 后填写。拉宽部分到位，但**标题重叠并没有真正解决**——人类用户在实际浏览器里截到第 06→07 之间，章节地标「自然语言处理与计算机视觉」与相邻小节标题完全压在一起（带 `07` 序号的章节名两行字与另一个标题占据同一像素区域，几乎不可读）。执行反馈里"49 对 0 重叠"的自检结论与实际不符。继续在本轮内迭代。

### 原因分析（讨论窗口判断，供执行参考）

执行采用的是**估算包围盒**：中文 13.4px/字、最多 13 字、地标行高 64、小节行高 50。在实际渲染中出现以下偏差：

1. **多行地标标题的高度被低估**。`自然语言处理与计算机视觉` 这种 12 字的章节名在实际样式下**会折行成两行**（在用户截图中可清楚看到），实际包围盒高度近 2× 行高。若估算按"行高 64"是单行 64px，则两行实际占 ~100–128px；下方若有相邻小节标题（按上下交替规则进入同一垂直位置），二者就会重叠在地标的第二行上。**这是当前最可能的根因**。
2. **包围盒宽度被低估**。`text-align: center` 的标题以锚点为中心向两侧展开宽度；估算"最多 13 字 × 13.4px = 174px"，但渲染时若有 letter-spacing / padding / 两端裕量，水平投影会更宽。两个**水平距离接近**的相邻标题（如行末弧转两侧）也会在水平方向重叠，估算检测不到。
3. **估算 vs 实测的根本问题**：估算结果会受字体加载、字距、CSS 变量、用户系统字体等影响；只要任意维度偏差几像素，本应"严格大于 0 重叠"的判定就被错判为"不重叠"。这就是为什么自检显示 0 对、用户截图却明显看到撞击。
4. （次要）章节地标按需求是"不翻边，但参与避让判定"。如果地标实际位置 / 实际尺寸与估算偏差较大，相邻小节即便被翻边也无法躲开真实的地标体。

### 期望的修正方向

**算法**：在现有 `buildTrail` 生成的小径基础上**叠加一层小幅扰动函数**，让路在节点之间出现局部的自然弯曲：

1. **数学模型**：扰动作用在曲线的**法向方向**（即垂直于切线、沿路宽方向的偏移）。对每个 Catmull-Rom / 贝塞尔片段（即相邻两节点之间），定义参数 `t ∈ [0, 1]`，扰动偏移：

   ```
   offset(t) = A * window(t) * noise(t, segIndex)
   ```

   - `window(t)`：**端点窗函数**，保证 `window(0) = window(1) = 0` 且 `window'(0) = window'(1) = 0` —— 即节点处偏移为 0 且切线方向连续（C¹ 平滑）。推荐 Hann 窗：`window(t) = sin²(π·t)`。这是**关键约束**：保证节点仍精确落在路上、相邻片段在节点处衔接平滑无尖点。
   - `noise(t, segIndex)`：低频"伪随机"曲线，可用 2–3 个不同频率正弦叠加（如 `sin(2π·t + φ₁) + 0.5·sin(4π·t + φ₂)`），相位 `φ` 用 `segIndex` 派生（**确定性**：同 segIndex 同 noise）。
   - `A`：振幅，建议初始 **3–6 px**（小幅，肉眼可见自然感但不夸张）；如执行视觉评审觉得 8 px 更自然也可，但**不得超过 10 px**，避免破坏路面宽 / 节点对齐 / 局部回旋。

2. **实现位置**：在 `buildTrail` 输出 SVG path 之前，把扰动应用到曲线采样点上：
   - 对每个片段以 K（如 24–48）个 `t` 步密集采样原曲线位置 `P(t)` 与切线 `T(t)`；
   - 计算法向 `N(t) = perp(T(t))`；
   - 输出扰动后位置 `P(t) + offset(t) * N(t)`；
   - 用短折线 / 高密度小贝塞尔重新串成一条 path。
   - 路面所有层（小径底色、虚线、章节分段染色覆盖层）必须**使用同一条扰动后的 path**，否则会层间错位。

3. **节点对齐硬约束**：扰动后的曲线**必须仍精确穿过每个节点的原坐标**（树苗、地标的 anchor 不动）。`window(t)` 在 `t=0` / `t=1` 处归零就是为此。

4. **章节分段染色边界**：分段染色当前按"节点弧长区间"覆盖在路上，扰动后弧长区间在原曲线上的端点是节点本身（偏移为 0），所以**边界自然落在原节点处**，无需额外处理；执行验证一遍即可。

5. **连续协调**：

```
noise(t, s) = sin(2π·t + φ₁(s)) + 0.5·sin(4π·t + φ₂(s))   ← 低频伪随机
φ₁(s) = ((s+1) · 1.7) mod 2π,  φ₂(s) = ((s+1) · 3.1) mod 2π   ← segIndex 派生 → 确定性
A_desktop = 4,  A_mobile = 2.5                    ← 峰值 ≈ A·1.5 ≈ 6 / 3.75 px（≤ spec 上限 10）
```

实现细节：
- **节段定义**：`nodeArcs = [0, baseArcs[0], …, baseArcs[N-1], total]`（共 N+1 段，含起点到首节点、末节点到终点两段）。沿 `pts` 遍历时，单调指针前进 `s` 使 `nodeArcs[s] ≤ cum[k] ≤ nodeArcs[s+1]`，O(n) 总成本。
- **法向**：用相邻 `pts[k-1]` 与 `pts[k+1]` 的有限差分求单位切线 `T`，法向 `N = (-T.y, T.x)`。
- **扰动应用**：`perturbedPts[k] = pts[k] + offset(t) · N`；`(x, y)` 保留 2 位小数压缩 path 字符数。
- **三层共用同一条 path**：`trailD = polylineD(perturbedPts)`，`segments` 用 `segPath(perturbedPts, cum, total, ...)`。`cum` 沿用原弧长（同 sample index），章节分段染色边界仍按"原节点弧长中点"取，两段在该公共采样点都用 perturbedPts → 染色边界**无错位**。
- **节点对齐硬约束**：`baseArcs[i]` 项位于 `nodeArcs` 数组里，`t` 在该 arc 处 = 0 或 1 → `window = 0` → `offset = 0` → 节点处 `perturbedPts == pts`，节点仍精确在路上。

### 还差什么

> 用户原话：「这个扰动可以更加平滑协调一点，现在的幅度是很不错的，但是有的地方突变的有点突兀。」

迭代 2 用 `offset(t) = A · sin²(πt) · noise(t, segIndex)`：每段独立的相位 / 频率。虽然 Hann 窗保证了节点处偏移 = 0、切线连续（C¹），但**有的地方仍然显得突兀**。最可能的根因：

1. **噪声在节点处"重启"**：相邻两段的 `noise(t, segIndex)` 是**独立函数**——上一段尾部的弯曲方向 / 节奏与下一段头部的弯曲方向 / 节奏**毫无关联**。虽然在节点那一像素是连续的（pinch 为 0），但视觉上仍能察觉"刚穿过节点马上往不同方向弯"的不协调。
2. **C¹ 不够，缺 C² 曲率连续**：`sin²(πt)` 在端点处一阶导为 0 但二阶导非零。视觉上"平滑感"主要由曲率连续性决定；C¹ 但曲率突变会被肉眼读作"折"。
3. **短段（U 形拐角附近）扰动频率显得太密**：每段固定采样数 / 局部 `t∈[0,1]`，导致短段被同样数量的 wobble 填充，**空间频率**比长直段密很多，视觉节奏不统一。

### 期望的修正方向

> **振幅保留迭代 2 的数值**（用户已认可），只动连续性 / 频率统一性。

**核心改动：从「分段相位 + 节点窗」改为「全局连续噪声 + 节点处轻柔 pinch」。**

1. **采用全局弧长参数化**：先把整条已平滑（向心 Catmull-Rom）小径按**总弧长** `s ∈ [0, S_total]` 均匀采样（如每 ~3 px 一个点 → 总点数 ~1000–2000），同时记录每个采样点对应的全局弧长 `s` 与就近节点位置。

2. **一条全局连续的噪声曲线**：

   ```
   noise(s) = sin(2π · s / λ₁ + φ₁) + 0.4 · sin(2π · s / λ₂ + φ₂)
   ```

   - `λ₁, λ₂` 为像素级波长（建议 `λ₁ ≈ 160 px`，`λ₂ ≈ λ₁ / 1.73` 用无理数比避免周期性）；
   - 相位 `φ₁, φ₂` **整条路全局固定**（不依赖 `segIndex`）；
   - 这样**节点前后是同一条噪声曲线**，没有相位 / 节奏断点 —— 跨节点的"突兀感"从根上消除。

3. **节点处的 pinch 改成更高阶窗**：把端点窗从 `sin²(πt)` 升到 **C² 连续**的窗：

   - 推荐 **`pinch(t) = sin⁴(π · t)`**（即 `sin²(πt)` 再平方）。它满足：`pinch(0)=pinch(1)=0`、`pinch'(0)=pinch'(1)=0`、**`pinch''(0)=pinch''(1)=0`**（即曲率在节点处也连续）。节点处的 C² 连续会消除"折感"。
   - 等价可选：`pinch(t) = (1 - cos(πt))² · (1 + cos(πt))² / 16`（同样 C²）。

4. **以弧长为准的局部归一化**：对每个采样点求其所在段的"段内弧长比例" `t_arc = (s - s_node_left) / (s_node_right - s_node_left)`，**用 `t_arc` 代入 pinch**（而不是几何 `t`）。配合短段 / 长段的弧长真实长度差异，让 pinch 在两侧节点附近都有合理的"渐入渐出"距离。

5. **最终偏移**：

   ```
   offset(s) = A · pinch(t_arc(s)) · noise(s)
   ```

   - **节点处** `pinch = 0` → 偏移 = 0、一阶导 = 0、二阶导 = 0 → 位置 / 切线 / 曲率三阶皆连续；
   - **段中部** `pinch ≈ 1`，扰动由全局 `noise(s)` 主导，相邻段共用同一相位 → 自然过渡；
   - **短段** pinch 在弧长尺度上自动收紧，与全局噪声相乘后短段振幅会更小 → 空间频率更统一、不再"短段过密"。

6. **路面所有层（底色 / 虚线 / 章节分段染色覆盖层）继续共用同一条扰动后 path**（迭代 2 已做到，不回退）。

7. **节点对齐硬约束不变**：扰动后曲线必须仍**精确穿过每个节点的原坐标**（49 小节 + 8 地标），误差 ≤ 0.5 px（沿用迭代 2 的实测口径）。

8. **确定性 / 稳定性**：全局相位 `φ₁, φ₂` 用固定常数（如 0 与 1.27）即可，**不再依赖 segIndex / 窗口尺寸**——同输入同输出，切换索引展开 / 收起 / ResizeObserver 重排，扰动几何**完全一致**。
