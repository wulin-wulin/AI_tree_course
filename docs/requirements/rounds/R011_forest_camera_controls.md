# R011 - 森林导览页相机交互改进（右键转视角 / 平移限位 / 最佳视角）

状态：Accepted

创建日期：2026-06-23

## 背景

R010 已把 `/ai` 章节导览改为深色倾斜 3D 树森林（vendor `scene3d.js` 自写球面相机控制）。实际体验后，用户认为森林页的**相机交互还不够好**：转视角能力弱、左键平移会把森林拖飞、重置的「最佳视角」不好看。本轮只聚焦 `/ai` 森林导览页的相机交互，不动数据、布局、阅读页与首页。

> 本轮基于 R010 已在代码中生效的森林实现继续打磨。R010 形式上尚未走完审核流程，但其森林实现是本轮的现实基线。

## 用户真实反馈

逐字记录：

1. 「这个界面的交互我觉得还不够好，可以将鼠标右键改成调整俯仰和方向角度的功能。」
2. 「目前的左键拖动没有限制，会导致可能用户拖动到很远的地方回不来，要加一个拖动范围限制。」
3. 「中间上方的刷新图标应该是回归最佳视角，但是目前我觉得这个最佳视角不是很好看，需要调整一下。」

## 当前实现现状（执行前必读，已从代码确认）

相机模型在 `src/forest/vendor/scene3d.js`：

- 球面相机绕地面注视点 `target`，状态 `this._state = { theta, r, target:{x,y} }`。
  - `theta`：方位角 / 朝向（绕竖直轴旋转）。
  - `r`：相机到 target 的距离（缩放，滚轮控制，范围 `[250, 12000]`）。
  - `phi`：俯仰角，**当前不是状态变量**，在 `_updateCamera()`（约行 217）里由 `r` 自动推导：`phi = 0.7 + 0.5 * min(1, r/4000)`。用户无法单独控制俯仰。
- 鼠标（`_setupControls()` 约行 172）：
  - `mousedown` 里 `_rot = (e.button === 2 || e.ctrlKey || e.metaKey)`。
  - 右键 / Ctrl / Meta 拖动 = 旋转模式，但**只用水平位移 `dx` 改 `theta`**，竖直 `dy` 被忽略；`theta` 被夹在 `_ROT = {thetaMin: -π/2-0.3, thetaMax: -π/2+0.3}`（约 ±17°）。
  - 左键拖动 = 平移，**直接写 `target.x/y`，无任何范围限制**。
  - 滚轮 = 缩放 `r`。
- 地图尺寸常量 `CANVAS_W=4000 × CANVAS_H=3000`，森林内容大致分布其中，中心约 `(2000, 1500)`。
- `resetView()`（约行 450）：只复位 `theta=-π/2` 和 `r=5000`，**没有复位 `target`**（平移后点重置，森林仍偏移——隐性 bug）。`phi` 随 `r` 自动得 1.2 rad。
- 初始加载视角由 `_state` 默认值 + `_setupControls()` 末尾的 `_updateCamera()` 决定，与 `resetView()` 不完全一致。
- React 侧 `src/components/ForestMapPage.tsx`：`⟳` 重置按钮在约行 114（`onClick={() => sceneRef.current?.resetView()}`）；RAF 渲染循环在约行 54（持续 `scene.render()`，所以相机状态一改下一帧就反映，无需手动重渲）。

## 本轮目标

让森林导览页的相机操作更顺手、不易迷失、默认视角更好看。具体三件事：右键自由转视角（俯仰+朝向）、左键平移加范围限位、重置/初始的最佳视角调好看。

## 具体需求

### 需求 1：右键拖动 = 同时调整俯仰角（pitch）与方向角（heading）

- 把 `phi`（俯仰角）改为**可由用户控制的独立状态变量**，从 `r` 解耦（移除 / 改写 `_updateCamera` 里 `phi = 0.7 + 0.5*min(1, r/4000)` 的自动推导）。
- 右键拖动时：
  - 水平位移 `dx` → 改方位角 `theta`（左右转朝向，沿用现有逻辑）。
  - 竖直位移 `dy` → 改俯仰角 `phi`（抬头 / 低头）。
- 给 `phi` 加范围夹紧，避免翻到地面以下或失去 3D 感：
  - 必须保证相机始终在地面之上（注意 `cz = r*cos(phi)`，需 `phi < π/2 ≈ 1.5708` 才有 `cz > 0`）。
  - 建议区间约 `phi ∈ [0.35, 1.30]`（从较俯视到接近地平线），**最终上下限由执行者按观感截图微调**。
- `theta`（方位角）范围当前仅 ±0.3 rad，偏窄，转起来不明显：**适度放宽**让「转方向」有存在感（例如 ±0.6~0.9 rad），但仍保留边界，避免标签 / 布局观感错乱。最终值执行者按观感定。
- 保留触控板兜底：`Ctrl/Meta + 左键拖动` 等同右键（旋转）。左键单独 = 平移，滚轮 = 缩放，三者互不干扰。
- 旋转灵敏度参考现有 `dx * 0.002`，`phi` 用相近量级（执行者可调到手感顺滑）。
- `resetView()` 与初始状态都必须显式设定 `phi`（见需求 3，二者须一致）。

### 需求 2：左键平移加范围限制（拖不飞）

- 给平移后的 `target.x / target.y` 加**范围夹紧**，使森林内容始终至少保留在视野内，用户拖不到「空旷虚无 / 回不来」的地方。
- 夹紧范围**优先按森林内容包围盒动态计算**：从 `layout.points` 的 `pos` 取 x/y 的 min/max，向外扩一个边距（例如内容跨度的 ~15%），**不要写死数字**，这样簇布局变化时仍自适应。退一步可用画布 `0..4000 / 0..3000` 加边距。
- 把夹紧抽成一个公共函数（如 `_clampTarget(x, y)`），平移分支与 `flyTo()`、`resetView()` 设定 `target` 时都经过它，保持一致。
- 可选：缩放越远视野越大，允许夹紧边距随 `r` 略放宽（执行者判断，非必须）。

### 需求 3：重置 / 最佳视角调好看，并修复 target 未复位

- 重新定义「最佳视角」，让 `⟳`（`resetView()`）回到一个**好看**的视角：
  1. **框住整片森林**：23 个簇尽量都在视野内，不过度留白，不被顶部栏（`#forest-topbar`，约 48px 高）遮挡。
  2. **有舒服的倾斜、能看出树的 3D 立体感**（不要太正俯视，也不要太贴地平线）。
  3. **居中在森林质心**（内容包围盒中心）。
  4. 与需求 1 的新 `phi` 状态一致（显式设定 `theta / phi / r / target` 四个量）。
- **修复 `resetView()` 未复位 `target` 的 bug**：重置时必须把 `target` 也复位到森林中心，否则平移后重置仍偏。
- **让「初始加载视角」与「重置视角」完全一致**（同一组 `theta / phi / r / target`），避免首屏和重置两种观感。
- `r` 最好按内容包围盒 + 相机 FOV 算到「恰好框住 + 留少量边距」，而不是写死 `5000`（写死也可，但要肉眼框得好）。
- 「好看」是主观标准：执行者必须按 `AGENT_PROTOCOL.md` 截图自检 `/#/ai`，反复微调 `phi / r / theta / target` 到自己看着满意为止，并在执行反馈里附自检截图说明与最终参数。

## 非目标

- 不改森林布局算法、`index.json` 数据、簇着色、LOD / 密度可见性逻辑。
- 不改阅读页、首页、搜索、图例、跳转知识簇下拉。
- 不引入 `OrbitControls` 等新依赖；沿用现有自写球面相机控制（若执行者认为换库明显更优，可在反馈里提出并说明，但默认不换）。
- 本轮聚焦桌面鼠标交互；**移动端触摸的俯仰 / 旋转手势不在本轮范围**（触摸无右键）。如顺手且不破坏现有可附带，否则记入 backlog。平移限位（需求 2）对触摸平移同样生效则更好。

## 执行反馈

> 由执行智能体完成后填写。

### 实现概况

全部改动集中在 `src/forest/vendor/scene3d.js` 的相机控制相关方法（`_setupControls` / `_updateCamera` / `flyTo` / `resetView` + 新增两个辅助方法），未触碰树工厂、布局、数据、阅读页与首页。核心是把俯仰角 `phi` 从「随 `r` 自动推导」改为「用户可控的独立状态」，并补上平移限位与按内容包围盒计算的「最佳视角」。React 侧 `ForestMapPage.tsx` 无需改动（`⟳` 仍调 `resetView()`，持续 RAF 渲染自动反映新状态）。

### 已完成需求

- **需求 1（右键转视角）**：`phi` 解耦为独立状态。右键 / `Ctrl|Meta+左键` 拖动时，`dx → theta`（左右转水平朝向，类似地图东西南北）、`dy → phi`（俯仰）。**方向（用户追加澄清）**：上滑 `dy<0` → 拉低视角（更贴地平线，`phi↑`）、下滑 `dy>0` → 拉高视角（更俯视，`phi↓`），即 `phi -= dy*0.0035`。`phi` 夹在 `[0.35, 1.30]`（始终 `phi<π/2`，相机在地面之上、保留 3D 感）。**水平朝向（用户追加澄清 + 根因修复）**：`theta` **不再夹紧**，右键左右拖动可绕森林 **360° 自由旋转**朝向（朝北→朝西→朝南，像地图罗盘转盘），灵敏度 `dx*0.004`。**根因**：本场景世界是 **Z 朝上**（地面 z=0、相机高度 `cz=r·cos(phi)`），但相机沿用 Three.js 默认 `camera.up=(0,1,0)`（落在地面内）。原参考项目只在 ±0.3 rad 窄范围转，掩盖了问题；一旦放开自由转方位角，in-plane 的 up 让方位旋转**退化/翻滚**，水平朝向转起来歪斜、看似没变——这正是用户反馈「右键左右根本没变化水平视角」的真正原因。**修复：`camera.up.set(0,0,1)`**，方位旋转即为干净的「转盘式」水平转向（地平线保持水平）。左键平移 / 滚轮缩放互不干扰，`_updateCamera` 不再自动改写 `phi`。
- **交互可靠性（根因修复配套）**：拖拽事件由 `mousedown`+`window mousemove` 改为 **Pointer Events + `setPointerCapture`**，确保右键拖动在真实浏览器里也能持续、可靠地收到 move（避免右键拖动丢事件）。新增 `dispose()` 解绑全部监听，`ForestMapPage` 卸载时调用，修复 StrictMode 双挂载残留重复监听的隐患。
- **需求 2（平移限位）**：新增 `_clampTarget(x,y)`；限位框 `_panBox` 由 `layout.points` 的 `pos` 包围盒外扩 15% 边距动态算得（不写死、随布局自适应）。左键平移、`flyTo`（知识点与知识簇两分支）、`resetView` 设定 `target` 时都过 `_clampTarget`，森林拖不出视野、回得来。
  - **平移方向跟手（用户追加澄清）**：原平移把屏幕 `(dx,dy)` 直接写世界轴 `target.x-=dx / target.y+=dy`，只在初始朝向 `theta=-π/2` 正确；右键转向后屏幕左右与世界轴错位，往左拖会朝别的方向滑。**修复：按当前 `theta` 把拖拽量投影到地面**——屏幕右向量 `(-sinθ,cosθ)`、前向量 `(-cosθ,-sinθ)`，`θ=-π/2` 时正好还原原公式，转任意朝向后平移都跟手。
  - **拖拽不再误进阅读页**：左键拖拽（平移）松手若落在树上，原 `click→raycast→openReading` 会误导航进阅读页。`ForestMapPage` 加点击/拖拽判定（`pointerdown` 记起点，`click` 时位移 >6px 视为拖拽、忽略），点击选树仍可用。
- **需求 3（最佳视角 + 修 target）**：新增 `_computeBestView()`，按内容包围盒质心定 `target`、按相机 FOV+aspect 反算 `r`（取竖直/水平所需较大者 ×1.2 留边距），`theta=-π/2`、`phi=0.8`。`resetView()` 现显式复位 `theta/phi/r/target` 四量（**修复了旧版只复位 theta/r、target 不复位的隐性 bug**）。**初始加载视角与重置视角共用同一组 `_best` 参数，完全一致**。

最终相机参数（含用户追加微调：默认俯角放平 + 竖直拖动方向反向 + 水平朝向自由旋转）：初始/重置 `theta=-π/2`（**不夹紧**，左右拖动可 360° 自由转）、`phi=1.0`（放平，夹紧 [0.35,1.30]）、`r=max(rY,rX)*1.02`、`target=` 内容质心约 `(1982,1577)`；平移限位框 = 内容包围盒 `x[574,3391]/y[236,2918]` 外扩 15%。右键拖动：`theta -= dx*0.004`（左右转朝向）、`phi -= dy*0.0035`（上滑拉低 / 下滑拉高）。

### 未完成或部分完成

- 移动端触摸的俯仰 / 旋转手势按非目标未做（触摸无右键）；但**平移限位对触摸平移同样生效**（同一 mousemove 分支）。
- 平移限位采用 spec 建议的 15% 边距，可把森林推到屏幕一角（仍完整可见、可重置回来），未进一步收紧；如需更「贴边即停」可后续调小边距。

### 执行中发现的问题

- **「右键左右不改水平朝向」根因**：相机 up 用了默认 `(0,1,0)`，但世界 Z 朝上，自由旋转方位角时退化/翻滚——改 `camera.up=(0,0,1)` 解决（详见需求 1）。教训：仅靠 Playwright 像素差确认「画面变了」不够，水平旋转必须肉眼确认是干净转盘、而非翻滚。
- `_computeBestView` 用 `this.camera.aspect` 反算 `r`；构造期相机 aspect 已由容器尺寸初始化，可用。`r` 在构造时算一次、不随窗口 resize 重算（与 vendor 原版一致），靠留白兜底，截图确认常见尺寸下框得住。
- 原 vendor 拖拽用 `mousedown`+`window mousemove`、且 React 卸载未解绑——改 Pointer Events + `dispose()` 一并修掉。
