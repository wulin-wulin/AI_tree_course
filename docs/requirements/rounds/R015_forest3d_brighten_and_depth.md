## 背景

R014 之后，项目在 `3DMap` 分支上把 Level 1 章节导览（`/ai`）从「2D 徒步长卷」整体换成了**真实的 3D 森林地图**（Three.js r0.184 + @react-three/fiber + drei，WebGL）。该 3D 工作此前**没有任何轮次文档**——R015 既承接这次方向切换，也修复它当前最突出的两个问题。

> 协议缺口说明：3D 地图是在 R014 之后实现的，但未走「先有 `Ready` 轮次再实现」的流程，`current_state.md` / `next_upgrade_prompt.md` 也未同步。R015 作为这摊工作的首份正式文档；3D 地图的「已实现现状」在本轮验收（连同 R013/R014）时一并回写 `current_state.md`。

人类用户在另一台机器上查看时发现：**最里层的 3D 视图太暗，且与开发机显示的颜色不一致**；同时**怀疑当前是不是真正的 3D**。

### 需求讨论窗口的技术核查结论（先答疑，再立需求）

1. **这是真正的 3D（已确认）。** 证据（`src/components/forest3d/ForestMapScene.tsx`）：透视相机（`fov 42`）、真实三维几何体（球簇白云 / 600×600 地面 / 圆柱树干 + 二十面体树冠）、方向光 + 阴影（`shadows` / `castShadow` / `receiveShadow`）、雾做地平线纵深、`MapControls` 平移缩放、相机三档极角俯仰。**不是 CSS 伪 3D，也不是贴图假 3D。**
2. **「感觉不像 3D」的原因**：① `MapControls` 设了 `enableRotate={false}`，相机被锁死、不能自由环绕 → 缺少视差，读起来像「一张倾斜的 2D 地图」；②（默认其实已是斜视档 `tiltIndex=1`/48°，**不是**正俯视，故非主因）；③ 树是「绘本扁平」造型 + `frameloop="demand"` 静止无动态，整体偏平面插画感。
3. **「太暗 / 跨机器颜色不一致」的根因**：`<Canvas>` 未显式设置 `flat` 或 `gl.toneMapping`，r3f **默认启用 `ACESFilmicToneMapping`**——它压暗中间调、降低饱和，使写入的十六进制颜色（如地面 `#bfe0a0`）渲染得比原色更暗更灰；叠加各机器显示器 gamma / GPU 色彩配置文件差异被放大成肉眼可见的不一致。光照本身也偏保守（环境光 0.85 + 单方向光 0.9）。

## 用户真实反馈

> 原话保留：

- 「最里面的 3D 视图太暗了，和我在另一台机器上显示的颜色是不一致的，我们需要改一下，亮一点。」
- 「我想确认现在的 3D 视图是不是真实的 3D 视图，我感觉不像是真实的 3D 视图。」

经需求讨论窗口可视化校准后，用户确认两项方向：

- **范围**：本轮不只调亮，**同时增强立体感**，让它看起来更像 3D。
- **目标观感**：**明亮通透绘本风**——颜色鲜亮、接近原色、明快饱和（类似明亮的儿童绘本 / 扫雷草地那种通透感），而非写实柔光。

## 已确认的关键决策

- **A. 调亮 = 先修根因，再补光。** 主修色调映射（去掉/弱化 ACES 对作者色的压暗），使渲染颜色接近设计稿原色、并在不同机器/显示器上尽量一致；再据此微调光照强度，达到「明亮通透」。**目标是颜色更准更亮更跨机一致，不是单纯把曝光拉满。**
- **B. 增强立体感（在调亮基础上叠加）。** 让 3D 感更明确，候选手段（执行智能体按观感取舍、不必全做）：① 允许相机**适度旋转**（开放有限角度的环绕，避免完全锁死；仍要防止转到地面以下或翻过头）；② 树 / 地形更有体积或更明确的明暗面；③ 保留默认斜视档。**以「一眼能看出是 3D」为准。**
- **C. 观感基准 = 明亮通透绘本风。** 调色调映射 + 打光时以此为锚；误区/语义色等既有约定不在本轮动。
- **D. 不推翻 3D 架构。** 本轮是在现有 Three.js / r3f 场景上调参与小幅增强，不重写渲染管线、不换技术栈、不改三级导航与路由。

## 本轮目标

让 `/ai` 的 3D 森林地图：① 颜色**明亮通透、接近设计原色、在不同机器上观感一致**，消除「太暗 / 跨机不一致」；② 立体感更明确，一眼能看出是真 3D（不再像倾斜的平面地图）。整体仍是和谐的绘本风森林，服务学习者的章节导览。

## 具体需求

### 1. 色彩管理与调亮（根因修复，最高优先级）

- **修色调映射**：在 `<Canvas>` 显式控制 tone mapping，使作者写入的颜色被准确还原（明亮通透绘本风通常意味着**关闭 ACES**，例如 r3f 的 `flat` 或 `gl={{ toneMapping: THREE.NoToneMapping }}`；若保留某种 tone mapping，须显式设定并调好 `toneMappingExposure`，不可依赖隐式默认）。
- **确保色彩空间正确**：输出走 sRGB（r3f 默认即如此），与作者十六进制色一致；避免双重 gamma。
- **据此补光**：在颜色还原正确后，再微调环境光 / 方向光强度（必要时加一盏补光或半球光 `hemisphereLight` 提亮阴影面）至「明亮通透」，但**保留方向光与阴影**以维持立体明暗，不要打成纯平无影。
- **跨机一致性**：去掉对隐式默认的依赖后，不同机器/显示器上的观感应明显更接近（受显示器物理差异限制无法 100% 相同，但要消除「一台正常一台发暗发灰」级别的差异）。
- 视需要同步微调**地面 / 天空 / 雾 / 树冠**等基础色，使整体在新色调映射下统一为明亮通透绿地森林（避免某些面在调亮后过曝发白或依旧发暗）。

### 2. 增强立体感

- **相机交互**：把 `MapControls` 的完全锁死旋转放开为**有限度的自由环绕**（开放方位角旋转、对极角设上下限，避免相机钻到地面下或翻到天上；保留现有平移、缩放、三档俯仰按钮）。目的是给出视差、让用户能转着看出是 3D。
  - 若放开旋转与现有「三档俯仰按钮 / 平移夹紧」逻辑冲突，执行智能体在**保留这些既有能力**的前提下协调（俯仰按钮仍可用、平移仍夹在地图范围内）。
- **体积感**（按观感取舍，不要求全做）：树冠 / 树干或地形可加强明暗面、轮廓或体积，使其在斜视/环绕下更立体；保持绘本风、不引入写实贴图。
- **默认视角**：保留默认斜视档（`tiltIndex=1`）。

### 3. 自检（按协议第 7 条，本轮强约束）

- 用项目 Playwright 截图工作流截 `/ai` 的 3D 地图（桌面 + 移动），覆盖**俯视 / 斜视 / 平视三档**，并演示旋转后的视角；**自己查看截图**核对：颜色是否明亮通透、是否接近设计原色、是否一眼像 3D；不满意就微调再截，直到合格再报告。
- 跨机一致性无法在单机完全验证，但执行智能体应说明已通过「关闭/显式化 tone mapping + 正确色彩空间」从机制上消除隐式默认带来的差异。

## 非目标

- 不改三级导航结构与路由；不动首页书架（Level 0）与知识点阅读页（Level 2）。

### 实现概况

- **根因修复（调亮 + 跨机一致）**：给 `<Canvas>` 加 `flat`（= `THREE.NoToneMapping`），关闭 r3f 默认的 `ACESFilmicToneMapping`，让作者写入的十六进制颜色按原色还原；色彩空间保持 r3f 默认 sRGB。这同时消除了「隐式色调映射叠加显示器/GPU 差异」导致的跨机器发暗发灰不一致。

## 执行反馈 2（再提亮一档，2026-06-16）

### 诊断（先定位「为什么第一版看不出变化」）

排查确认**不是渲染器/色彩管理 bug**（three r0.184 默认开启 ColorManagement + sRGB 输出，`<Canvas>` 未设 `linear`，hex 颜色被正确转线性渲染）。第一版观感与旧版接近，有两个真实原因：

1. **地面（受光亮处自我抵消）**：第一版去掉 ACES 的同时也下调了光强；「ACES + 强光」与「NoToneMapping + 中等光」在受光亮处会落到几乎相同的输出值，于是地面看起来没变。等于两个改动互相抵消。
2. **树（默认全未读 → 全用深色渲染）**：每章有 `accent`（鲜艳）与 `dark`（很深，如 `#175c49`/`#115184`/`#912742`）两套色；旧逻辑「未读 = 深色 `dark` + 78% 半透明 + 缩小」。默认进度 0/49（全未读），导致**整片森林都在用深色 `dark` 半透明渲染**——这才是树发暗发闷的主因，并非颜色没上到位。
